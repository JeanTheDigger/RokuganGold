# 56.20 Dungeon Traps — LOCKED

Owner-approved 2026-06-16. Hidden hazards placed on ASCII-map missions (s56) by
defenders who know how to make them. The player detects them (passively), then
disarms, routes around, or springs them.

**Setting basis (not invented):** the Crane **Daidoji Iron Warrior / Harrier**
have "Hunting (Traps)" and lay improvised traps that deal +1k1 / +2k1 (s29.2,
s11.7). Trap-laying is therefore a Crane / scout / bandit signature, not a
universal capability — a map only carries traps if its roster includes a unit
with the Hunting:Traps skill.

## Data model

Traps are a **data layer, not tiles** (a hidden trap must not render). New on
`AsciiMapData`:

```
@export var traps: Array = []   # each: {x, y, type, detect_tn, disarm_tn, damage_roll, state, placed_by_skill}
```

`state`: `HIDDEN` → `DETECTED` → (`DISARMED` | `SPRUNG`). A `HIDDEN` trap renders
as normal floor; a `DETECTED` or `SPRUNG` trap may overlay a glyph.

## Trap types (LOCKED — full set of 5)

| Type | Effect | Resolves via |
|---|---|---|
| PIT | Fall: 2k2 damage; Athletics TN 15 to catch the edge (half / no damage) | WoundSystem + Athletics roll |
| DART / ARROW | Ranged attack vs **flat-footed Armor TN** (5 + armor bonus, per the s40 stealth model), 2k2 | IndividualCombat attack |
| SNARE / NET | **Entangled** condition, escape TN 20 (oni-web parity, s54.5) | existing Entangled condition |
| ALARM / TRIPWIRE | No damage — raises nearby enemy **AlertState** (Unaware → Alert) | CombatController noise / alert |
| DEADFALL | Area collapse: 3k2, adds rubble to `destroyed_tiles`, blocks the tile | WoundSystem + destroyed_tiles |

## Detection — passive per-turn (LOCKED)

Each turn, every `HIDDEN` trap within **2 tiles** of the character **and in their
FOV** rolls against the character's passive **Perception + Hunting** vs the trap's
`detect_tn`. On success the trap becomes `DETECTED` (the player can route around
it or attempt a disarm). No action cost. Crane Daidoji / high-Hunting characters
spot more by virtue of their skill. There is **no** explicit SEARCH action and
**no** always-visible mode.

## Disarm (LOCKED)

Adjacent to a `DETECTED` trap, the character rolls the **better of Hunting (Traps)
or Sleight of Hand** vs `disarm_tn`. Hunting is the Crane trapper's craft; Sleight
of Hand is generic delicate handwork, so a non-Crane PC can still defuse a trap.
Missing the TN by **10 or more springs the trap**.

## Trigger (LOCKED)

Stepping onto a `HIDDEN` trap (via `MovementSystem.check_step`, which gains a trap
lookup) springs it and resolves its effect. A `DETECTED` trap is a known tile to
step around — moving onto it deliberately also springs it.

## Sprung-trap noise (LOCKED)

Only **physically loud** traps make noise when sprung and raise nearby enemy
AlertState: **PIT** and **DEADFALL**. **DART** and **SNARE** are silent (they
hurt / entangle without blowing an infiltration). **ALARM / TRIPWIRE** always
raises AlertState — that is its entire purpose.

## Numeric values (LOCKED as PROVISIONAL — revisit after first live run)

- Damage: Pit 2k2, Dart/Arrow 2k2, Deadfall 3k2.
- Pit edge-catch: Athletics TN 15 (success halves; or avoids — implementer's
  choice at build time, document which).
- Snare: Entangled, escape TN 20.
- Detect / disarm TN tiers: **crude 15 / set 20 / concealed 25 / master 30**.

These are calibrated against L5R 4e scale and comparable hazards (oni-web TN 20,
the s40 flat-footed Armor TN model) but are not GDD-sourced numbers; they are
marked PROVISIONAL in code and may be retuned once a mission is played live.

## Placement

Deterministic from the mission seed. Template-appropriate: cave dead-ends and
chokepoints, the approach to the objective room, entrances; scout-template
perimeters (Forest Approach, Stockade, Hilltop). Density scales with the seed's
`strength`. A trap is placed **only if** the roster contains a Hunting:Traps unit
(Crane Harrier, trap-savvy bandit) — otherwise the map has none. ALARM traps
especially suit the stealth model (they convert a quiet infiltration into a fight).

## Integration points

`MovementSystem.check_step` (trigger + step-around), `FovSystem` (detection
gating), `CombatController` (loud-sprung / ALARM → AlertState),
`MissionPopulator` / template generators (placement), `AsciiMapCombatOrchestrator`
(DISARM as a turn-based action).

## Implementation (2026-06-16)

- `AsciiMapData.traps: Array` — the data layer (HIDDEN traps never render).
- `simulation/trap_system.gd` (TrapSystem, pure): `TrapType`/`TrapState`/`Quality` enums,
  all PROVISIONAL constants, `make_trap`, `is_loud`/`alerts_on_spring`, `trap_at`,
  `attempt_detect` (Perception+Hunting vs detect_tn → DETECTED), `attempt_disarm`
  (better of Hunting:Traps/Sleight of Hand vs disarm_tn; miss by ≥10 springs it),
  `trigger` (Pit 2k2 + Athletics-15 half / Dart 2k2 vs flat-footed ATN / Snare→Entangled
  escape TN 20 / Alarm alert-only / Deadfall 3k2 + RUBBLE delta), and the placement layer
  (`place_traps`, `roster_has_trap_layer`, `quality_for_strength`).
- `CombatController` (the exploration/stealth layer where traps live): springs a trap on
  the tile the player enters, runs passive per-turn detection (`detect_traps`, FOV-gated),
  and exposes `try_disarm_trap`. Loud/alarm springs route through `_emit_noise` →
  AlertState. **All paths no-op when `map.traps` is empty**, so trap-free missions are
  unaffected (the 154 existing CombatController tests use trap-free maps).
- `MissionBuilder.assemble()` calls `place_traps` after population.

**Placement gate is PROVISIONAL.** The roster carries no per-unit skill data, so
`TRAP_LAYER_UNIT_TYPES` (currently the two scout units, HIRUMA_SCOUT / NEZUMI_SCOUT) is the
stand-in for "a Hunting:Traps unit is present." The exact trap-laying unit set is a
GDD-silent design call awaiting owner confirmation/expansion.

Validated by static review + parse-trace (Godot not available in this environment; GUT not
run). Player-facing DISARM input + DETECTED-trap rendering land with the combat UI — the same
boundary as all existing combat actions.
