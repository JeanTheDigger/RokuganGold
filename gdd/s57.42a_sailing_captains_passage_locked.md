# 57.42a. Sailing, Captains & Passage — Implementation Lock

Owner-approved 2026-06-06. s57.42 and s57.43 are the design source (treated as
LOCKED as written); this file records the implementation scope and the values the
code consumes. Code: `simulation/sailing_system.gd`, `shared/ship_data.gd`
(`owner_id`, `departure_tick` added).

## Scope (headless core)

`SailingSystem` (pure class) implements the captain/passage logic and the s57.43
voyage formulas faithfully to s57.42/43. The ship ASCII Lesser Zone, the AT_SHIP
context + action allow/block list, voyage-event resolution, passenger-manifest
generation, and REQUEST_PASSAGE/JUMP_OVERBOARD as live pipeline ActionIDs are
deferred to the UI / NPC-engine layers.

## Confirmed / locked values

- **A1 — Captain Sailing minimums (s57.42.3):** small coastal/river (Sampan,
  Merchant Barge, Kobune) = 1; oceangoing merchant (Sengokobune) = 3; heavy
  warship (Koutetsukan, Atakebune) = 4. **TORTOISE_OCEANGOING = 3** — bucketed as
  oceangoing; PROVISIONAL (s57.42.3 gives no Tortoise minimum).
- **A2 — Under-qualified self-captain penalty:** −2k0 on Sailing rolls (s57.42.3).
- **A3 — Captain succession (s57.42.5):** acting captain = living crew with the
  highest Sailing; tiebreak Insight Rank, then Status. None with Sailing → -1
  (catastrophic-incident peril). Emphasis tiebreak from s57.42.5 deferred (needs
  the per-character Sailing emphasis + current-need model).
- **A4 — REQUEST_PASSAGE (s57.42.6):** Category 11, 0 AP, throttle 2 / IC day;
  1-IC-day refusal cooldown per captain.
- **A5 — Acceptance (s57.42.7):** standing-orders refusal and schedule
  incompatibility are hard refuses; Acquaintance+ (disposition ≥ 11) rides free;
  below that, koku + personality lean must bridge the gap to 11 (1 lean point ≈
  1 koku of goodwill). Leans: Jin +5 (struggling traveler), Seigyo +3 (koku
  offered), Rei +2 (high-Status [≥ 4.0] or polite). Polite refusal → no
  disposition shift; rude refusal → −1..−3.
- **A6 — Owner-granted passage (s57.42.7):** 3-point Obligation on the requester.
- **A7 — Embarkation (s57.42.8):** at `departure_tick`, accepted passengers
  co-located in the port settlement get `aboard_ship_id` set; others are left
  behind. Disembark clears `aboard_ship_id` and places the passenger in the
  destination.
- **A8 — Pirate interception (s57.43.7):** chance = Strength × 10% per ship;
  Strength 4+ → Naval Mass Battle, 1–3 → Deck Skirmish.
- **A9 — Shipwreck drift (s57.43.6):** landfall/rescue chance day 1 = 10%
  (30% in Mantis waters), 2 = 25%, 3 = 40%, 4+ = 60%; 6-IC-day ceiling, then
  death at sea.

## Deferred (UI / NPC-engine — needs Godot or deep integration)

Ship ASCII Lesser Zone (SHIP_INTERIOR) + voyage play map; AT_SHIP context enum +
the per-action allow/block list wired into context-action lists; voyage events
(pirate interception firing, arrival route-disruption); passenger-manifest
generation from the NPC pool; REQUEST_PASSAGE / JUMP_OVERBOARD / INTERVENE_CAPTAIN
as live ActionIDs; named-crew REPORT_TO_SHIP travel; owner-override letter flow.
The headless `SailingSystem` provides the rules/decision/formula logic these
layers will call.
