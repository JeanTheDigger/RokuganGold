# 56.21 Within-Map Depth Gradient — LOCKED

Owner-approved 2026-06-16. Defines "depth" for ASCII-map missions (s56) as a
**within-map difficulty gradient**, not classic stacked roguelike floors.

## Decision (LOCKED)

**Option A only — within-map depth gradient.** The GDD frames depth as a single
map that gets harder/stranger with distance from the entrance, never as
floor-to-floor descent:

- "the **deeper** the player walks, the less the world looks like the mortal
  realm" (Spiritual Insurgency, s56.16),
- "**deeper layers** hold older, stronger revenants" (Corrupted Burial, s56.10),
- ravine "back-loaded value" (s56.11).

**Option B (true stacked generated floors) is NOT built.** No multi-level
`MissionSession`, no `DOWN_STAIR` generation, no cross-level state persistence,
no per-floor regeneration. The one-way-descent-vs-ascend question is therefore
moot — there is only ever one map per mission.

## Mechanic

- Tag each tile/region with `depth` = path-distance from `entry_pos`.
- `MissionPopulator` weights stronger roster units into higher-depth regions; the
  **leader sits at maximum depth** (deepest from the entrance).
- Spiritual maps shift their tile palette with depth (already the s56.16 concept —
  deeper = less like the mortal realm).

## Cost / scope

Small — reuses the existing single-map pipeline; adds a `depth` field on the map
plus populator weighting. No pipeline rebuild. Applies to every template.

## Implementation

- `AsciiMapData.depth_grid: PackedInt32Array` + `compute_depth_grid(entry_x, entry_y)`
  (8-directional BFS over passable + door tiles from the player entry; unreachable = -1),
  `depth_at(x, y)`, `has_depth_grid()`.
- `MissionBuilder.assemble()` computes the player entry (`get_player_entry`) and fills the
  depth grid **before** population.
- `MissionPopulator._gather_candidates()` orders the candidate slots deepest-first when the
  map carries a computed depth grid, so earlier-processed (stronger) roles and the leader take
  the deepest slots. Falls back to depth-agnostic tier order when depth is uncomputed
  (backward-compatible for `populate()` called on a raw generated map).

Spiritual-map palette shift with depth is the separate s56.16 concern (the depth grid is
available to it); no palette code is added here. **Option B (stacked floors) remains
unbuilt.** Implemented 2026-06-16; headless (generation/population only, no combat-UI dependency).
